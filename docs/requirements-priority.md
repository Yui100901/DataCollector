# AI 浏览器自动化需求优先级文档

## 项目重新定义

DataCollector 将从一个基于 Playwright 的简易爬虫框架，重新定义为一个由 AI 驱动 Playwright 的浏览器自动化工具。

新的项目目标是：

> 用户用自然语言描述浏览器任务，系统由 AI Agent 观察页面、决定下一步操作、调用 Playwright 工具执行动作，并最终返回结构化结果、执行日志、截图和可复现步骤。

## 目标用户

- 需要可编程浏览器自动化能力的开发者。
- 希望减少选择器编写成本的数据采集人员。
- 需要构建可重复浏览器流程的自动化任务开发者。
- 希望通过 CLI 或 API 暴露浏览器任务能力的内部工具开发者。

## 优先级定义

- **P0 - 基础能力 / MVP 阻塞项**：第一个可用版本必须完成。没有这些能力，项目无法体现新的方向。
- **P1 - 核心产品能力**：MVP 之后必须补齐，用于形成真正可用的 AI 浏览器自动化工具。
- **P2 - 可靠性 / 规模化 / 开发体验**：提升稳定性、可观测性、可维护性和可扩展性。
- **P3 - 可选能力 / 未来扩展**：后续有价值，但不影响第一阶段产品成型。

## P0 - 基础能力 / MVP 阻塞项

### 产品范围

- [x] 将项目定位从爬虫框架改为 AI 浏览器自动化运行时。
- [x] 明确核心流程：任务输入 -> 页面观察 -> AI 决策 -> Playwright 工具执行 -> 结果输出。
- [x] 明确首个支持的任务类型：单浏览器会话自动化任务。
- [x] 明确首个支持的输出类型：包含步骤历史和提取数据的 JSON 运行结果。
- [x] 确定公开包名和 CLI 命令名。

### 工程基础

- [x] 新增 `pyproject.toml`。

- [x] 将源码整理为标准 Python 包结构，例如 `datacollector/`。
- [x] 保持 Python 作为主开发语言。
- [x] 保持 Playwright async Python 作为浏览器自动化引擎。
- [x] 新增 `.env` 支持，用于模型 API Key 和运行配置。
- [x] 修复现有 README 编码问题。

### 浏览器运行时

- [x] 将现有 `AsyncPageManager` 重构为浏览器运行时模块。
- [x] 支持浏览器启动和关闭。
- [x] 支持 context 和 page 生命周期管理。
- [x] 支持 headed 和 headless 模式。
- [x] 支持 viewport、user agent、headers、proxy、locale、timezone 配置。
- [x] 为高级用户保留直接访问 Playwright 对象的能力。

### AI Agent MVP

- [x] 选择第一版 AI Agent 实现方案：Pydantic AI + OpenAI Responses API。
- [x] 定义最小 Agent 循环：
  - 观察当前页面。
  - 让模型决定下一步动作。
  - 执行模型选择的工具。
  - 将工具执行结果返回给模型。
  - 在任务完成或失败时停止。
- [x] 定义浏览器操作系统提示词。
- [x] 定义最大执行步骤数。
- [x] 定义任务总超时时间。
- [x] 定义模型配置项：provider、model、temperature、max output tokens。

## P1 - 核心产品能力

### 页面观察能力

- [x] 为 AI Agent 生成紧凑的页面观察结果。
- [x] 页面观察结果包含 URL、标题、可见文本摘要、可交互元素和截图路径。
- [x] 尽可能加入 accessibility tree 或基于 role 的元素摘要。
- [x] 对 DOM 文本进行压缩，避免发送过多 token。
- [x] 在每一步执行结果中记录当前页面状态。

### 结构化提取

- [x] 允许用户指定期望的输出 schema。
- [x] 支持从页面内容中提取结构化 JSON。
- [x] 支持提取列表。
- [x] 支持提取表格。
- [x] 支持提取链接和媒体 URL。
- [x] 使用 Pydantic 模型校验提取结果。

### 工具调用协议

- [x] 所有工具都定义强类型参数。
- [x] 所有工具都定义强类型返回值。
- [x] 工具返回结果包含 success、失败原因、截图路径、当前 URL 和可选提取数据。
- [x] 统一工具层错误处理方式。
- [x] 区分可重试错误和不可重试错误。

### Agent 运行时

- [x] 维护步骤历史。
- [x] 维护任务记忆：目标、已完成动作、失败记录、已提取数据。
- [x] 支持带原因的优雅失败。
- [x] 支持任务完成条件判断。
- [x] 支持用户可读的执行总结。

### 安全控制

- [x] 增加域名白名单和黑名单。
- [x] 对危险操作增加确认机制。
- [x] 对危险操作分类：付款、删除、发送消息、账号变更、表单提交。
- [x] 在日志中隐藏敏感信息。
- [x] 不在模型输出中暴露 API Key、Cookie、密码或 Token。

## 建议里程碑

### M1 - 项目基础改造

目标：让仓库在结构和文档上体现新的项目方向。

包含：

- P0 产品范围。
- P0 工程基础。
- P0 浏览器运行时。
- README 基础重写。

完成标准：

- 项目可以在本地安装。
- 用户可以通过新的运行时启动浏览器。
- 主要文档不再以传统爬虫框架作为项目定位。

### M2 - AI 控制浏览器 MVP

目标：通过 AI 工具调用执行自然语言浏览器任务。

包含：

- P0 AI Agent MVP。
- P0 最小 Playwright 工具集。
- P0 CLI MVP。

完成标准：

- 用户可以从 CLI 运行任务。
- Agent 可以导航、点击、输入、观察页面并停止。
- 运行结果包含 JSON 格式的步骤历史。

### M3 - 结构化自动化产品

目标：让工具能支持真实数据采集和可重复流程。

包含：

- P1 页面观察能力。
- P1 结构化提取。
- P1 工具调用协议。
- P1 Agent 运行时。
- P1 安全控制。

完成标准：

- 用户可以请求结构化数据。
- 输出结果经过 schema 校验。
- 失败运行能提供有用诊断信息。
- 危险操作受到保护。

### M4 - 可靠的开发者工具

目标：让项目可维护、可调试。

包含：

- P2 可观测性。
- P2 持久化。
- P2 测试。
- P2 开发体验。

完成标准：

- 每次运行都有日志、截图和 trace 产物。
- 测试覆盖运行时、工具层和 Agent 循环。
- 开发者可以通过清晰示例新增工具。

### M5 - 服务化和工作流扩展

目标：从本地 CLI / 库扩展为服务和工作流平台。

包含：

- P3 API 服务。
- P3 Web UI。
- P3 工作流引擎。
- P3 集成。

完成标准：

- 可以远程提交和查看任务。
- 支持长任务或带审批的工作流。

## MVP 明确不做

- [ ] 第一版 MVP 不做 Web UI。
- [ ] 基础 Agent 循环跑通前，不引入 LangGraph。
- [ ] 除非项目方向变化，否则不整体迁移到 TypeScript。
- [ ] 第一版 MVP 不支持分布式浏览器执行。
- [ ] 不将反爬绕过作为主要产品目标。
- [ ] 不让 AI Agent 对高风险操作进行完全自主执行。
